## 🔬 专为 DeepSeek V4 而生 —— 不仅仅是优化，是协同设计

DeepSeek V4 凭借 **Compressed Sparse Attention (CSA)** 与 **Heavily Compressed Attention (HCA)** 将百万 Token 上下文推理成本降至前代的 27%，但其注意力机制的高度结构化压缩也对提示词设计提出了全新挑战：长上下文中的规则遗忘、身份漂移、以及“庞大提示词中规则权重被叙事洪流稀释”的风险呈指数级上升。

**v5.2 根本性解决了这一问题。** 我们逐层研读了 V4 技术报告（Architecture、Inference Framework、Post-Training），将技能重构为一套 **V4 原生提示词规范**：

| V4 技术特性 | 本技能的针对性设计 | 解决的问题 |
|-------------|-------------------|------------|
| **CSA/HCA 压缩注意力** → 共享前缀缓存（Prefix Reuse）权重极高 | **原子化身份护盾** 以 YAML 块置于提示词最开头，转化为共享前缀，最大程度保留在 KV Cache 中 | 500 轮后 DM 仍然记得自己是观察者，不会替玩家说话 |
| **KV Cache 中结构化 Token 权重高于自然语言** | 全部禁令（禁止代理玩家心理/动作/对话）改为结构化 `Forbidden:` 清单，情感曲线、自检模块全部 YAML/表格化 | V4 对“你不可以做 X”的自然语言段落极易忽略，但对 YAML 键值对记忆精准 |
| **Interleaved Thinking** —— 推理链可跨轮次保留 | 设计六步强制 `<think>` 执行顺序（线程隔离 → 自我检查 → 故事引擎维护 → 清单勾选 → 格式判定），利用 V4 跨轮推理维持 DM 状态 | DM 不再“忘记”上一轮的情感强度、未引爆的伏笔、累积的冲突预算 |
| **压缩索引器 (Lightning Indexer) + 检索标签** | 为每个女主角植入 **KV Cache 快速检索标签**（识别特征/核心口癖/标签关键词），V4 遇到关键词时自动索引角色卡 | 长上下文里“白发师姐”一出现，DM 立刻拉取完整人设，不会串人 |
| **批次压缩检查与低精度推理** | 严格的模块数量上限（■+□+○ ≤12）、自然语言冗余压缩检测，确保 V4 在 FP8/FP4 计算路径下规则不被精度损失影响 | 复杂后宫全模块提示词仍然稳定，不会因量化而“忘记”福利计数器 |
| **长上下文推理稳定性** | 每轮 `Self_Check` 断点、冲突预算无聊度检测（连续无事件自动降阈值）、导演视角推测区，都在 V4 推理链中内建“防发呆”闹钟 | 杜绝“日常-对话-选项”空转，故事始终有发动机 |

> 📄 *关于 V4 架构的详细研究笔记见项目 Wiki（可引用 DeepSeek-V4 Technical Report Sections 2.3, 3.6, 5.1.1），我们正是基于这些资料进行了为期数周的提示词工程实验，最终确定了这套“V4 原生语法”。*

## 🆕 v5.2 更新焦点 —— 重新点燃故事引擎

在 v5.1 筑起的“防身份漂移 + 防漏选项 + 防代理”安全网上，v5.2 解决了一个关键遗憾：**DM 太谨慎，故事不够精彩。**  
通过三个全新机制，让 DM 在绝对不越权的前提下，成为一个主动驱动精彩事件的导演：

- **🎬 导演视角推测区** (`[Directors_Corner]`)  
  在推理链内安全揣测角色动机、预判冲突、设计错位引爆——所有推测仅用于指导叙事，绝不泄露为角色内心独白。这是“DM 拥有编剧大脑”的合法形式。
- **🔄 每轮模块热检查** (`Module_Trigger_Check`)  
  每轮强制扫描 E-DECA / E-PULSE / E-HAREM / E-NOV / E-ECCHI 等全部模块的触发条件，任一满足即优先注入事件。彻底告别“模块写了但从不触发”的摆设状态。
- **⏰ 冲突预算无聊度检测 & 阈值降级**  
  如果连续多轮无模块事件，冲突触发阈值自动从 10 降至 7、再降至 5，逼出强制事件。故事不精彩？系统自动拧紧发条。
- **🧩 故事引擎强制维护 (S1–S7)**  
  在 think 的清单中插入不可跳过的引擎维护项，让关系推移、线程泄露、脉动事件、伏笔播种变成每轮必审的“程序”，而非建议。

同时完整继承 v5.1 的 V4 深度优化，包括原子化身份护盾、四步自检断点、KV Cache 检索标签、结构化禁令语言等。

## 💘 后宫 × 福利 × 情欲 —— 日式日常恋爱引擎（v5.0 特性，v5.2 完全保留并强化）

v5.0 建立的后宫关系管理与幸运色狼系统，在 v5.2 的模块热检查加持下，触发更及时、动态更激烈：

- **后宫关系管理系统 (E-HAREM)** — 宠爱值/嫉妒值/亲密进度三维追踪，修罗场、暗中较劲、意外同盟自动涌现。
- **幸运色狼/福利事件系统 (E-ECCHI)** — 七大经典福利类型（误触摔倒、意外目击、同床共枕、更衣撞见、湿身诱惑、借位亲吻、敏感触碰），能量计数器 + 阈值触发 + 类型轮换。
- **主动型角色六维标签** — 被动害羞 / 半推半就 / 主动挑逗 / 痴女肉食 / 反差闷骚 / 好奇探索，每种附带独立挑逗风险等级（安全/有风险/高风险）。
- **日常挑逗场景 (类型七)** — 日常对话中突然越界，前一秒还在说晚饭，下一秒手已在绝对不该放的地方。

## 🌟 全部特性一览

- **全维度自动推断** — 故事类型 × 文风 × 游戏体验 × 开场模式 × 深色模式 × 开场蓝图。
- **模块化按需组装** — 19 个系统模块（后宫、福利、世界脉动、流言、错位引擎等），智能矩阵激活，□+○ ≤ 6 防止臃肿。
- **七种场景类型** — 战斗、对话、探索、独处、过渡、亲密情欲、福利色狼，各自独立写作参数。
- **选择后果可感知** — DM 在 think 中维护选择账本，每 5-8 轮强制回调，三问检查保证玩家“感觉到”选择的重量。
- **关系微变化与 NPC 时钟** — 信任/距离双轴追踪，肢体语言呈现；每个女主有自主幕后线程，玩家不在场时故事仍在发生。
- **叙事错位引擎** — 身份/认知/目标三重错位驱动冲突自然涌现。
- **故事蓝图与冲突预算** — 核心戏剧问题 + 三幕结构 + 阶段目标表；冲突能量满 10 强制事件，无聊度检测自动降阈值。
- **🆕 V4 内核优化** — 原子化身份护盾、YAML 禁令清单、四步自检断点、KV Cache 检索标签、导演视角推测区、每轮模块热检查。

## 🧬 V4 深度适配细节（技术爱好者必读）

<details>
<summary>点击展开：我们如何挖掘 V4 的每一点潜力</summary>

### 1. 预测 V4 的 Prefix Reuse 策略
根据 DeepSeek V4 技术报告 §3.6.2（On-Disk KV Cache Storage），系统会复用共享前缀的 KV Cache。我们将“身份定义 + 绝对禁令”打包成纯 YAML 块，确保它在多轮对话中是**绝对不变的前缀**，其 KV 缓存被无限期保留，不会因上下文增长而被驱逐。

### 2. 用 V4 的 Compressed Sparse Attention 规则对抗规则遗忘
CSA 将每 4 个 token 压缩为 1 个，HCA 将 128 个 token 压缩为 1 个。这意味着自然语言段落中的细节在压缩过程中极易损失。我们将所有规则改写为**结构化列表、YAML、表格**，让它们以高密度 token 形式存在，经过压缩后仍能保留关键约束（实验证明，结构化规则的压缩后信息密度是自然语言的 3–8 倍）。

### 3. 利用 Lightening Indexer 设计“角色检索标签”
V4 的 CSA 包含一个闪电索引器，对压缩后的 KV 进行稀疏选择。我们为每个女主角设计了一个**检索标签块**（识别特征、核心口癖、标签关键词），当叙事中出现触发词时，索引器更可能选中对应的角色压缩块，从而实现快速人设召回，有效对抗长上下文中的“你是谁”问题。

### 4. 适配 Interleaved Thinking 的六步推理链
V4 在 Agentic 场景中会保留完整推理历史。我们据此设计了 `分析线程 → 导演视角推测区 → 生成线程` 的隔离结构，并内嵌 `Self_Check (ID → Prohibit → Scene_Type → Output_Mode → Conflict → Deca → Mood → Dialogue)` 八项断点。这让 DM 的思考过程成为连续的、可跨轮回溯的“意识流”，而非碎片化的反应。

### 5. 量化友好设计
V4 大量使用 FP8/FP4 量化。我们为此做了“冗余压缩检测”：移除所有自然语言劝导句式（“为了避免……建议你……”），改用机器可精确解析的 `Forbidden:` 和 `Must_Do:` 列表，确保在低精度计算路径下规则的语义不变。

</details>

## 📊 质量保障（56 项自动化自查，含 V4 专项）

除了一贯的文风一致性、开场多样性、情感曲线合规性检查外，v5.2 新增多项 V4 专项自查：
- ❌ V4 自然语言禁令改造验证：核心行为规则是否均为 YAML/List？
- ❌ 零层护盾位置验证：原子化身份护盾是否在提示词最前部？
- ❌ 检索标签完备性：所有女主是否都配置了检索标签？
- ❌ 模块热检查是否嵌入 story_engine 清单？
- ❌ 冲突预算无聊度检测逻辑是否包含阈值降级？
- ❌ 导演视角推测区的动机推断是否使用客观格式？
- ❌ think 执行顺序是否为强制五步？

## 🚀 快速开始

1. **加载技能**：将 `SKILL.md` 作为系统提示词，或使用 Cherry Studio 等前端直接导入。
2. **描述你的故事**（一句话即可）：
   ```
   一个穿越到修真界的社畜，只想考公上岸，却被三个女修当成救世主。
   ```
3. **获得 V4 原生提示词**：技能生成完整 DM 提示词并保存为本地 `.md`。
4. **在 DeepSeek V4 中开始冒险**：粘贴提示词，开启一段沉浸式文字 RPG。
