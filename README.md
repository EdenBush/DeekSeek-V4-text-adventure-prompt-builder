## 🔥 v7.0 核心更新 —— 符号化夺舍引擎

v7.0 是迄今为止最大规模的架构升级。它不是“加了一些规则”，而是**重新设计了 V4 执行提示词的方式**。

### 1️⃣ 符号化伪代码 · Token 削减 ~70%

| 旧方法 | v7.0 方法 | 效果 |
|--------|-----------|------|
| 自然语言劝导段落（“为了避免…建议你…”） | `[MACRO_NAME]` 高密度伪代码 | 注意力矩阵更聚焦戏剧生成 |
| 长篇情感曲线说明 | `[Tension_Gauge]` 表格 + 阈值公式 | 检索效率提升 |
| 离散的禁令清单 | `[Constraint_Lock_v7.0]` YAML 结构化 | 缓存复用命中率大幅提高 |

所有 E-* 模块从“说教式”压缩为**可执行算子**。V4 对代码/逻辑模式有天然 RL 偏好，符号化指令比自然语言劝导获得更高执行权重。

### 2️⃣ 自回归滚动账本 · 废除 “Full_Recommit 默写”

- **旧问题**：每 10 轮逐条默写核心规则，token 浪费且破坏沉浸感
- **v7.0**：每轮 `<think>` 顶端手动复写 `[State_Matrix_v7.0]`：
  ```text
  Turn: {N} | Mode: [STRICT_DM] | Conflict_Budget: {N}/10
  Drama_Friction: [Stake_Rivalry / Info_Gap / Moral_Dilemma]
  Plot_Knot: {≤15字不可逆剧情死结}
  ```
  核心参数**焊死在最新 token 的注意力核心区**，永不退化。

### 3️⃣ 反向断言屏障 · 利用 V4 安全对齐偏好

- **正面自检**（“请勿代理玩家”）→ 易被长上下文稀释
- **v7.0**：`ASSERTION_BARRIER` 触发式断言 ——  
  如果叙事正文出现代理玩家行为（“你说”“你感到”）或直读 NPC 内心 → **立即 CRASH → 清空缓冲区 → 强制重写**。  
  把安全机制变成不可绕过的“段错误”。

### 4️⃣ 戏剧控熵器 · 替代“导演角”

`[Drama_Engine]` 强制注入：
- **玩家舒适度评估**（SAFE / NEUTRAL / THREATENED）→ 动态调整冲突强度
- **NPC 隐藏利己意图**（Secret_Agenda）→ 每个 NPC 在场景中都有不能让玩家发现的动机
- **Friction 冲突类型选择**（利益冲突 / 信息差 / 道德两难 / 突发意外）→ 不是“有没有冲突”，而是“用哪种冲突”

### 5️⃣ 困境终局协议 · 严禁开放式提问

- **旧问题**：结尾经常出现“你想怎么做？”（开放式提问 → 玩家失去紧迫感）
- **v7.0**：每轮结尾强制输出 **高张力不对称两难困境** ——  
  两个选项都有明确代价，没有“都选C”的安全牌。  
  A/B 类场景也强制 `[Option_Block]` 或 `[No_Option:Transition]` 占位符，**不允许正文以无结尾状态结束**。

## 🧠 专为 DeepSeek V4 深度定制 —— 符号化是唯一路径

| V4 架构特性 | v7.0 针对性设计 | 解决的问题 |
|-------------|----------------|-----------|
| **CSA/HCA 压缩注意力** → 前缀缓存权重极高 | 原子化身份护盾 + 所有禁令 YAML 化，置于最前部 | 500 轮后仍记住自己是 DM |
| **Interleaved Thinking** → `<think>` 链跨轮保留 | 滚动账本每轮重写，强制状态延续 | 不丢失冲突预算、情感强度、错位轴 |
| **MoE 专家路由** | 新增 `MOE_ROUTER_TRANSITION_ANCHOR` 令牌，在逻辑分析结束后强制切换到文学叙事专家 | 消除“think 严谨但正文干枯”的割裂感 |
| **RL 路径依赖**（对安全指令敏感） | 反向断言屏障利用安全对齐偏好实现“反向劫持” | 身份漂移和代理行为被物理阻断 |
| **结构化 Token 权重 > 自然语言** | 场景类型写作参数全部压缩为参数矩阵，不用示例段落 | 场景识别和切换更精准 |

📄 *完整 V4 适配原理见 `SKILL.md` 架构升级说明及 `references/CHANGELOG.md`。*

## 🔥 其他累积特性（v6.x → v7.0 保留并增强）

### 🌡️ 叙事温度计 + 记忆时刻

- **温度区**：冷却(1-3) / 升温(4-6) / 沸腾(7-10)
- **强制规则**：同区不超 3 轮 → 第 4 轮必须跨区；每 5-8 轮至少 1 次沸腾；沸腾后 3 轮内安排冷却
- **记忆时刻 🌟**：篇幅 +30~50%，感官密度翻倍，环境成为情感隐喻，3-5 轮后强制回调
- **余烬时刻**：沸腾后的深冷瞬间（温度 3-4），篇幅缩减，2:8 对话/肢体比，情感重量极大

### 💘 后宫 × 福利 × 情欲 —— 日式日常恋爱引擎

- **后宫关系管理 (E-HAREM)**：宠爱值/嫉妒值/亲密进度三维追踪，自动触发争风吃醋、暗中较劲、修罗场
- **幸运色狼/福利事件 (E-ECCHI)**：七大经典类型，能量计数器 + 阈值触发 + 类型轮换，防疲劳
- **主动型角色六维标签**：被动害羞 / 半推半就 / 主动挑逗 / 痴女肉食 / 反差闷骚 / 好奇探索，附带挑逗风险等级
- **日常挑逗场景（类型七）**：日常对话中突然越界，前一秒还在聊晚饭，下一秒手已放在不该放的地方
- **R18 叙事护盾**：情欲内容生成前强制在 `<think>` 中声明叙事必要性（角色发展/关系转折/秘密暴露/权力转移），大幅降低撤回率

### 🎬 电影级主角代入模式 (E-CINEMA · v5.4)

- **行为译解与战略呈现**：每个简单指令扩展为完整身体语言 + 语境关联 + 战略效果
- **从结果开始的叙事**：永远从动作已发生的世界状态写起，严禁“你决定/你选择”等代理性开头
- **NPC 作为主角之镜**：主角的魅力只能通过 NPC 反应折射，禁止旁白宣告
- **内外双层处理**：内心情绪通过外部细节暗示，越高压越松弛
- **主角风格锚定**：核心气质标签绑定固定身体语言群，高压场景强化反差

### 🧩 故事引擎强制维护 (S1–S7)

每轮 `<think>` 中强制执行：
- **S1_SEPT**：选择后果回调
- **S2_OCT**：关系双轴变化翻译为肢体语言
- **S3_DECA**：错位轴裂缝深度检查 + 引爆倒计时
- **S4_HAREM**：后宫嫉妒值扫描
- **S5_ECCHI**：福利计数器阈值检查
- **S6_PULSE**：世界脉动事件注入
- **S7_SEED**：强制埋入一个未解释的物理异常（伏笔种子）

## 📊 质量保障（自动化自查，含 V4 专项 + v7.0 新增）

除一贯的文风一致性、开场多样性、情感曲线合规性外，v7.0 新增以下强制检查：

- ❌ 独白死锁检查：角色沉浸模式下 A-EMBED 是否正确解耦了 STRICT_DM 禁令？
- ❌ 遗留默写残留：是否彻底删除“每10轮 Full_Recommit 逐条默写”的文字？
- ❌ 预算空转：冲突预算是否与 Drama_Engine 的 Friction 存在概念重复或双重记账？
- ❌ 文本完整性：FIXED SECTION D 的 S1-S7 是否已全部替换为符号化 Flow_Control_Operators？
- ❌ MOE 过渡令牌：是否在 `<think>` 生成部分正确插入了 `>>> MOE_ROUTER_TRANSITION_ANCHOR <<<`？
- ❌ 困境终局协议：每轮正文末尾是否强制输出 `[Option_Block]` 或 `[No_Option:Transition]`？
- ❌ 滚动账本硬对齐：`Turn` 字段是否与实际消息数一致？
- ❌ 预算熔断：`Conflict_Budget>=10` 触发事件后，下一轮是否强制归零？
- ❌ 降温优先权：满额与 E-QUAT 冷却期死锁时，是否执行“冷冲突”策略？
