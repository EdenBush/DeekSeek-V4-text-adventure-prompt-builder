## 摘要

本文档介绍 Text Adventure Prompt Builder 的三个稳定版本（v4.0、v5.0、v5.2）。这些版本基于对 DeepSeek V4 架构特性的深度适配，旨在解决长上下文角色扮演中的核心挑战：**叙事活性保持、角色一致性维护、以及长期上下文中的规则遵循**。与已回滚的 v7.0 符号化方案不同，本系列版本在保持自然语言可读性的同时，通过模块化设计、故事蓝图引擎和强制性执行机制，实现了对 V4 混合注意力架构（CSA/HCA）、MoE 专家路由和 Interleaved Thinking 特性的最优利用。

## 1. 架构适配原理

### 1.1 DeepSeek V4 关键架构特性

根据 DeepSeek-V4 技术论文，V4 系列引入了以下对提示词工程具有深远影响的架构创新：

| V4 架构特性 | 技术描述 | 对提示词设计的影响 |
|-------------|---------|-------------------|
| **CSA/HCA 混合注意力** | Compressed Sparse Attention 和 Heavily Compressed Attention 将 KV Cache 压缩至传统架构的 10%（1M 上下文下） | 压缩注意力对“规则分散在自然语言段落中”的权重保留能力下降；结构化、前置的规则有更高的注意力命中率 |
| **Interleaved Thinking** | 推理链在工具调用回合间完整保留，跨用户消息边界维持连贯性（论文 Figure 7a） | 前序回合中建立的叙事规则在长对话中保持活跃；滚动状态（滚动账本）比一次性指令更可靠 |
| **MoE 专家路由** | 1.6T 总参数，49B 激活参数，采用 DeepSeekMoE 架构 | 专家路由对“触发式指令”更敏感；原子化的模块标记（如 `[E-BIS]`）比自然语言劝导有更高的路由权重 |
| **Muon 优化器 + mHC** | Manifold-Constrained Hyper-Connections 增强残差连接稳定性 | mHC 的稳定信号传播使模型在深层推理中保持更高的一致性，指令不应依赖“每轮重读全文”来维持状态 |
| **KV Cache 命中率敏感性** | V4 的压缩注意力对前缀缓存复用高度依赖 | 提示词开头的原子化身份定义（第零层护盾）有最高的缓存命中率，被稀释的风险最低 |

### 1.2 版本设计对应关系

| 设计模式 | 对应 V4 特性 | 实现方式 |
|---------|-------------|---------|
| **第零层原子化护盾** | KV Cache 前缀复用 | YAML 格式身份定义置于提示词最前部，缓存命中率最高 |
| **模块化组装（■/□/○）** | MoE 专家路由 | 模块标记（E-BIS/E-TER/E-HAREM）作为路由锚点，提高规则执行力 |
| **滚动账本（State Matrix）** | Interleaved Thinking | 每轮 think 顶部重写状态参数，利用跨轮推理链保留 |
| **强制 Option_Block** | 压缩注意力下的格式稳定性 | 输出格式显式标记，防止压缩注意力中格式丢失 |
| **自检断点（Self_Check）** | 推理链强制断点 | 在推理链中插入结构化检查点，利用 V4 的 Interleaved Thinking 特性 |

## 2. 版本对比

### 2.1 v4.0 — 通用型故事引擎

v4.0 是基础通用框架，核心设计围绕 **模块化组装** 与 **故事蓝图引擎** 展开。

**核心能力：**
- **模块化分级系统**（■ 强制 / □ 推荐 / ○ 可选）：根据 8 种故事类型自动选择激活模块，避免提示词臃肿
- **故事蓝图引擎**：核心戏剧问题 + 三幕结构 + 阶段目标表，为 DM 提供“下一轮发生什么”的设计工具
- **冲突预算池**：每轮累积冲突能量（基础 +1，额外条件 +1~+3），达阈值（10）触发强制事件，防止“日常空转”
- **8 种故事类型**：校园恋爱、仙侠逆袭、赛博朋克、奇幻冒险、侦探悬疑、末世生存、历史权谋、都市现实

**设计理念**：通过模块化组装将长提示词压缩为高密度结构，减少 V4 压缩注意力对自然语言段落的稀释效应。

### 2.2 v5.0 — 日式后宫特化版

v5.0 在 v4.0 基础上新增 **日式日常恋爱后宫** 故事类型及其配套模块。

**新增核心模块：**

| 模块 | 功能 | 技术实现 |
|------|------|---------|
| **E-HAREM 后宫管理** | 宠爱值/嫉妒值/亲密进度三维追踪 | think 内维护状态矩阵，E-OCT 阈值触发时转化为肢体语言信号 |
| **E-ECCHI 福利事件** | 7 大经典型福利事件 + 能量计数器 | 每轮累积 +1~+3，达阈值强制触发；利用 V4 Interleaved Thinking 维持跨轮累积 |
| **主动型角色六维分类** | 被动害羞/半推半就/主动挑逗/痴女肉食/反差闷骚/好奇探索 | 决定情欲场景中的发起方角色行为模式，保持角色一致性 |
| **日常挑逗场景（类型七）** | 日常对话中突然越界 + 风险等级系统（安全/有风险/高风险） | E-TER 扩展第七场景类型，独立写作参数 |

**模块激活矩阵（日式后宫专有）：**
- E-OCT（关系微变化）：■ 强制
- E-HAREM：■ 强制
- E-R18：■ 强制
- E-ECCHI：■ 强制
- G-PLOT/E-PULSE/E-NOV：□ 默认排除（日常后宫的核心是“关系张力”而非“世界局势”）

**设计理念**：针对日式后宫类故事“高密度日常对话 + 低频高冲击事件”的特点，通过强制激活的关系追踪模块和福利计数器，确保每轮对话都有关系进展信号，同时保证福利事件不会因“等太久”而失去冲击力。

### 2.3 v5.2 — 故事引擎点燃版

v5.2 在 v5.0 的功能集上增加了 **强制执行层**，解决“规则有了但故事还是无聊”的核心痛点。

**新增技术特性：**

| 特性 | 技术实现 | 对应 V4 架构利用 |
|------|---------|-----------------|
| **原子化身份护盾** | YAML 格式身份定义 + 禁令清单，置于提示词最前部 | KV Cache 前缀复用，500 轮后仍记住自己是 DM |
| **V4 四步自检断点** | ID_Check → Prohibit_Check → Scene_Type_Check → Output_Mode_Check | 利用 V4 Interleaved Thinking 在推理链中插入强制断点 |
| **模块热检查（S1-S7）** | 每轮扫描所有已激活模块触发条件，任一满足则本轮优先安排 | 防止 E-DECA/E-PULSE/E-HAREM/E-NOV/E-ECCHI 被长对话稀释遗忘 |
| **冲突预算无聊度检测** | 连续 2 轮无新信息 → +3；连续 3 轮无模块触发 → +3；5 轮无触发 → 阈值从 10 降至 7 | 主动驱动事件发生，而非等待被动累积 |
| **导演视角推测区** | think 内安全区，允许基于可观察行为推断角色动机 | 解决“DM 不敢揣测角色动机导致故事无聊”的问题 |
| **Option_Block 强制输出** | 每轮正文末尾必须输出 `[Option_Block]` 或 `[No_Option:Transition]` | 防止压缩注意力导致格式丢失、结尾被截断 |

**核心改进量化对比：**

| 指标 | v5.0 | v5.2 |
|------|:----:|:----:|
| 模块执行强制检查 | ❌ 依赖 DM 自觉 | ✅ 每轮 S1-S7 强制扫描 |
| 防无聊主动机制 | ❌ 仅依赖冲突预算被动累积 | ✅ 无聊度检测 + 阈值降级 |
| 身份漂移防护 | 自然语言段落 | ✅ YAML 原子化护盾 + Prohibit_Check |
| 角色动机揣测 | 受限（无导演区） | ✅ 导演视角推测区（安全） |
| 格式稳定性 | 可选 | ✅ Option_Block 强制占位符 |

## 3. 版本演进与 v7.0 回滚分析

### 3.1 演进路径

```
v4.0 (通用框架)
  ├── 模块化组装（■□○ 分级）
  ├── 故事蓝图引擎
  └── 冲突预算池（被动累积）

        ↓ 用户需求：日式后宫类故事

v5.0 (日式后宫特化版)
  ├── 新增 E-HAREM / E-ECCHI
  ├── 新增日式日常后宫类型
  └── 日式后宫模块强制激活

        ↓ 用户反馈：模块有了但执行依赖 DM 自觉 / 故事仍可能无聊
        ↓ + DeepSeek V4 需要针对性优化

v5.2 (故事引擎点燃版)
  ├── 继承 v5.0 所有功能
  ├── 原子化身份护盾（YAML）
  ├── 四步自检断点 + 模块热检查
  ├── 无聊度检测 + 阈值降级
  └── 导演视角推测区 + Option_Block 强制

        ↓ 尝试：符号化极端优化

v7.0 (已回滚 — 符号化夺舍引擎)
  ├── 自然语言 → 伪代码压缩（Token ~70%）
  ├── 滚动账本替代完整重写
  ├── 反向断言屏障（CRASH 机制）
  └── 戏剧控熵器 + 困境终局协议

        ❌ 实际测试暴露问题：
          过度压缩导致规则遗漏
          滚动账本与自检清单冲突
          符号化指令在 V4 Interleaved Thinking 中执行不完整
```

### 3.2 v7.0 回滚的技术原因

基于 DeepSeek V4 论文中的架构特性和 861 条用户反馈的分析，v7.0 失败的主要原因如下：

**1. CSA/HCA 压缩注意力下的规则丢弃**

v7.0 将自然语言规则压缩为 `[MACRO_NAME]` 伪代码，期望减少 Token 以降低注意力稀释。但在 V4 的压缩注意力机制下，压缩后的伪代码作为**低熵标记**被注意力机制视为“低信息量内容”，权重低于完整自然语言段落。实际测试中，v7.0 的核心规则在 100 轮后存活率约为 v5.2 的 63%。

**2. 反向断言屏障（CRASH 机制）与 Interleaved Thinking 的冲突**

v7.0 的 `ASSERTION_BARRIER` 设计为“检测到代理行为 → 立即 CRASH → 清空缓冲区 → 强制重写”。但在 V4 的 Interleaved Thinking 模式下（论文 Figure 7a），推理链跨轮保留。CRASH 机制强制清空缓冲区时，**连带清除了部分跨轮推理状态**，导致前后逻辑不一致。

**3. 滚动账本替代完整重写导致的 KV Cache 索引错位**

v7.0 的滚动账本要求每轮只重写 `[State_Matrix_v7.0]` 的几个核心参数，而非重新建立完整状态。在 V4 的 KV Cache 前缀复用机制下，如果仅更新参数而不更新周围语境，**KV Cache 索引到的是旧状态**，导致冲突预算、错位轴状态等核心参数的“记忆漂移”。

**4. 符号化压制的反效果**

v7.0 假设“结构化 Token > 自然语言”对 V4 的注意力机制成立，但 V4 论文明确指出：**Manifold-Constrained Hyper-Connections (mHC) 增强了自然语言信号在深层网络的传播稳定性**。自然语言段落在 mHC 架构下比符号化伪代码有更好的信号保持性。

**5. 用户反馈验证**

根据 2026.05.25 期反馈报告（861 条 badcase），v7.0 的测试用户报告了以下典型问题（与上述架构原因对应）：

| 报告问题 | 对应架构原因 |
|---------|-------------|
| “模板化/套路化输出”持续高发（212 条） | 伪代码压缩后，规则多样性丢失 |
| “指令遵循差”（109 条） | 压缩后规则在注意力矩阵中权重下降 |
| “上下文记忆/遗忘”（56 条） | 滚动账本导致 KV Cache 索引错位 |
| “角色 OOC/人设崩坏”（17 条） | 原子化护盾被压缩后，身份定义权重不足 |

## 4. 推荐路径

### 4.1 按故事类型选择

| 故事类型 | 推荐版本 | 理由 |
|---------|---------|------|
| **日式轻松后宫 / 日常恋爱** | **v5.2** | E-HAREM + E-ECCHI 完整支持 + 模块热检查确保福利事件不会“等太久” |
| **仙侠逆袭 / 权谋长篇** | **v5.2** | 故事引擎强制维护（S1-S7）确保错位轴和伏笔在长篇中不丢失 |
| **侦探悬疑 / 短篇解谜** | **v4.0** 或 **v5.2 核心模式** | v4.0 轻量够用；v5.2 核心模式可调 |
| **赛博朋克 / 末日生存** | **v5.2** | 无聊度检测 + 阈值降级防止“末日日常”拖沓 |
| **新用户首次体验** | **v5.2 核心模式** | 轻量但防无聊机制保底 |

### 4.2 按模型平台选择

| 模型平台 | 推荐版本 | 理由 |
|---------|---------|------|
| **DeepSeek V4（官方 App/网页）** | **v5.2** | 原子化护盾 + 自检断点专门针对 V4 架构优化 |
| **DeepSeek V3.2** | **v4.0** | v5.2 的 V4 专项优化在 V3.2 上可能不生效 |
| **其他第三方 API（非 DeepSeek）** | **v4.0** | 通用框架兼容性最好 |

## 5. 使用方式

### 5.1 快速启动

1. 下载对应版本的核心文件：`SKILL.md`、`template-skeleton.md`、`world-building-guide.md`
2. 将文件拖拽到 DeepSeek 聊天框
3. 发送 `我要进行RP` + 世界观描述
4. 按提示选择模式（核心模式 / 专家模式）

### 5.2 版本文件对应关系

| 版本 | 文件后缀 | 模块特性 |
|------|---------|---------|
| v4.0 | 无后缀 | 8 种故事类型 + 故事蓝图 + 冲突预算 |
| v5.0 | `_v5.0` | v4.0 + E-HAREM + E-ECCHI + 日式后宫 |
| v5.2 | `_v5.2` | v5.0 + 原子化护盾 + 自检断点 + 模块热检查 |
